Fluxo de dados

Este documento descreve o fluxo de dados da ferramenta de formulários e PDF na perspectiva técnica, alinhado ao modelo corporativo e complementado com o comportamento das versões que disponibilizam rascunho local.

Entrada

Usuário insere dados manualmente nos formulários HTML servidos estaticamente.

Processamento

  • O preenchimento, a composição dos campos e a geração do PDF ocorrem no navegador; as consultas externas descritas abaixo processam apenas os dados mínimos necessários a cada funcionalidade.
  • Dados mantidos em memória (RAM) durante a sessão de preenchimento e geração do PDF.

Integrações externas da solução

Para funcionalidades específicas, o navegador faz requisições a serviços externos. Cada serviço recebe somente o dado funcional indicado abaixo, além do IP público de origem e dos metadados técnicos inerentes à requisição:

Serviço Finalidade Dado funcional transmitido
ViaCEP Consultar endereço. CEP enviado no caminho da requisição.
BrasilAPI Alternativa para consulta de endereço quando a consulta principal não retorna resultado. CEP enviado no caminho da requisição.
api.kstrtech.com.br Consultar municípios da unidade federativa selecionada. Sigla da UF enviada no caminho da requisição.
api.ipify.org Obter o IP público para incluí-lo como evidência técnica no PDF. Nenhum campo do formulário; o serviço identifica o IP público de origem da própria requisição e o retorna ao navegador.

Os provedores podem registrar o IP de origem e metadados de acesso conforme suas próprias políticas. O PDF gerado não é enviado a esses serviços; o conteúdo integral do formulário não é enviado.

Modelo corporativo original (minimização máxima): ausência de uso de localStorage, sessionStorage ou IndexedDB para dados pessoais — estado puramente efêmero.

Versões implantadas com recurso de rascunho: pode existir uso controlado de localStorage (ou equivalente) apenas para permitir retomar o preenchimento no mesmo navegador/dispositivo, com:

  • eliminação disponível via Descartar rascunho;
  • expiração automática: descarte do rascunho 24 horas após o último salvamento (módulo rascunho-ttl.js), sem opção de retenção indefinida; para rascunhos antigos sem horário registrado, o prazo começa na primeira abertura após a atualização, conforme informado no modal;
  • finalidade limitada à conveniência do usuário no mesmo dispositivo, até eliminação por expiração, Descartar rascunho ou limpeza local do navegador;
  • sem envio desses dados ao servidor da aplicação para armazenamento remoto do formulário.

Geração

  • Biblioteca JavaScript gera o PDF localmente no dispositivo.

Saída

  • Download direto para o dispositivo do usuário.

Descarte

  • Após gerar o PDF, os dados permanecem no formulário aberto, no rascunho local e em cópias temporárias pendentes de transferência entre formulários até a expiração, o descarte explícito ou a limpeza do armazenamento local.
  • Expiração automática: o rascunho, os dados do formulário e as cópias temporárias pendentes são excluídos 24 horas após o último salvamento (rascunho-ttl.js), com notificação na sessão aberta e descarte silencioso ao reabrir a página; no modal de proteção de dados o titular pode apagar o rascunho agora ou mantê-lo apenas por 24 horas. Rascunhos de versões anteriores sem horário registrado iniciam esse prazo na primeira abertura após a atualização, conforme informado no modal.
  • Rascunho local é removido imediatamente quando o usuário aciona Descartar rascunho.
  • O armazenamento local não substitui os sistemas corporativos oficiais nem constitui registro funcional oficial; a exclusão no Hub não alcança informações já incorporadas a esses sistemas (ver Aviso de Privacidade, § 7).

Observação — O que não há (por desenho)

Não há, nos termos desta solução:

  • Backend aplicacional obrigatório para guardar o formulário completo nos servidores desta app;
  • API própria para receber os campos preenchidos para conclusão do PDF;
  • Banco de dados central nesta aplicação para os dados digitados no formulário;
  • Envio obrigatório dos dados do formulário para servidores para gerar o PDF;
  • Logs de aplicação contendo payload de formulários com dados pessoais;
  • Chaves de acesso no código-fonte — apenas verificadores derivados (SHA-256 + salt) existem no guard.js.

Controle de acesso (quando ativo)

Além do fluxo de preenchimento, páginas protegidas utilizam sessionStorage para:

  • Armazenar um token aleatório (gerado via crypto.getRandomValues());
  • Armazenar o timestamp de expiração da sessão;
  • Armazenar o path da rota autenticada.

Estes dados de sessão não contêm a chave de acesso inserida pelo usuário, não são transmitidos a servidores e são limpos automaticamente ao fechar a aba ou ao acionar Encerrar acesso.

Infraestrutura de hospedagem/CDN pode gerar logs operacionais sem conteúdo do formulário — devem ser considerados no inventário de tratamentos quando aplicável.
